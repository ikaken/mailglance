# リリース手順

mailglance の新しいバージョンを、GitHub Releases に公開する手順です。公開すると、インストール済みのアプリに、更新の案内が出ます。

## 初回だけ：Secrets を登録する

Release のワークフローが、更新ファイルに署名するために、秘密鍵とそのパスワードを使います。GitHub の Secrets に、次の 2 つを登録します。

| 名前（そのまま入力） | 入れるもの | 元のファイル |
|---|---|---|
| `TAURI_SIGNING_PRIVATE_KEY` | 秘密鍵のファイルの**中身すべて** | `C:\Users\ikake\.tauri\mailglance.key` |
| `TAURI_SIGNING_PRIVATE_KEY_PASSWORD` | パスワード | `C:\Users\ikake\.tauri\mailglance.key.password` |

### 1. 値をクリップボードにコピーする

値を画面に表示せず、クリップボードに入れる方法です。PowerShell で、1 つずつ実行します。

```powershell
# 秘密鍵の中身をコピー
Get-Content -Raw "$env:USERPROFILE\.tauri\mailglance.key" | Set-Clipboard
```

```powershell
# パスワードをコピー
Get-Content -Raw "$env:USERPROFILE\.tauri\mailglance.key.password" | Set-Clipboard
```

メモ帳でファイルを開いて、全選択してコピーしても構いません。ファイルの中身は、1 行の文字列です。先頭や末尾に、余計な空白や改行を足さないでください。

### 2. GitHub に登録する

1. ブラウザで、リポジトリを開きます：https://github.com/ikaken/mailglance
2. 「**Settings**」タブを開きます。
3. 左のメニューの「**Secrets and variables**」を開き、「**Actions**」を選びます。
4. 「**New repository secret**」を押します。
5. 「Name」に、`TAURI_SIGNING_PRIVATE_KEY` と入力します。「Secret」に、1 でコピーした秘密鍵の中身を貼り付けます。「**Add secret**」を押します。
6. もう一度「**New repository secret**」を押します。「Name」に、`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` と入力します。「Secret」に、パスワードを貼り付けます（先にパスワードをコピーし直してください）。「**Add secret**」を押します。

### 3. 登録を確認する

PowerShell で、次を実行します。名前だけが表示されます（値は表示されません）。

```powershell
gh secret list --repo ikaken/mailglance
```

次の 2 行が出れば、成功です。

```
TAURI_SIGNING_PRIVATE_KEY
TAURI_SIGNING_PRIVATE_KEY_PASSWORD
```

### 4. クリップボードを空にする

秘密鍵やパスワードが、クリップボードに残らないようにします。

```powershell
Set-Clipboard -Value " "
```

### 5. 鍵のバックアップを取る

まだ取っていない場合は、今取ってください。**秘密鍵をなくすと、インストール済みのアプリが更新できなくなります**（手動での入れ直しが必要になります）。

- `mailglance.key` と `mailglance.key.password` を、パスワード管理ツールなどの、安全な場所に保管します。
- 他人に渡したり、GitHub などに上げたりしないでください。

## リリースの手順（毎回）

初回（`v0.1.0`）も、2 回目以降も、同じ手順です。以下は、`0.2.0` を例にしています。

### 1. バージョンを揃える

5 つのファイルにバージョンがあります。スクリプトで、まとめて変えます。

```powershell
node scripts/set-version.mjs 0.2.0
node scripts/check-version.mjs
```

最後に、`All versions are 0.2.0.` と出れば、成功です。

> 初回（`v0.1.0`）は、今のバージョンが `0.1.0` なので、この手順は不要です。

### 2. main にマージする

バージョンを変えた場合は、PR を作って、main にマージします。PR では、CI が自動で動きます（バージョンの一致、型チェック、Rust のテスト）。CI が成功してから、マージしてください。

### 3. タグを付けて、プッシュする

**main の最新のコミット**に、タグを付けます。

```powershell
git fetch origin
git tag v0.2.0 origin/main
git push origin v0.2.0
```

> タグの名前は、`v` ＋ バージョン（`v0.2.0`）です。ファイルのバージョンと一致しないと、ワークフローは失敗します。
> タグが main にないときも、失敗します。

### 4. ビルドの完了を待つ

1. リポジトリの「**Actions**」タブを開きます。
2. 「**Release**」のワークフローを開きます（`v0.2.0` と書かれたもの）。
3. すべてのステップに緑のチェックが付くのを待ちます。初回の実績は、**約 10 分**でした。

コマンドで確認する場合：

```powershell
gh run list --repo ikaken/mailglance --workflow release.yml --limit 3
gh run watch --repo ikaken/mailglance
```

### 5. 下書きのリリースを確認する

1. リポジトリの「**Releases**」を開きます。
2. 「**Draft**」と書かれた、`mailglance v0.2.0` を開きます。
3. 「Assets」に、次のファイルがあることを確認します。

| ファイル | 内容 |
|---|---|
| `mailglance_0.2.0_x64-setup.exe` | インストーラー |
| `mailglance_0.2.0_x64-setup.exe.sig` | 更新用の署名 |
| `latest.json` | アプリが更新の有無を調べるためのファイル |

4. 「`latest.json`」の中身を確認します。下書きのファイルは、ブラウザでは開けません。次のコマンドで、ダウンロードして確認します。

   ```powershell
   gh release download v0.2.0 --repo ikaken/mailglance --pattern latest.json --dir "$env:TEMP/rel" --clobber
   Get-Content -Raw -Encoding utf8 "$env:TEMP/rel/latest.json"
   ```

   - `"version"` が、`0.2.0` になっている。
   - `"signature"` に、長い文字列（440 文字ほど）が入っている。
   - `"url"` が、`https://api.github.com/repos/ikaken/mailglance/releases/assets/<数字>` の形になっている（tauri-action の仕様です。ブラウザ用の URL ではありません）。

### 6. 公開する

> **公開した時点で、インストール済みのアプリに、更新の案内が出ます。** 必ず、手順 5 を確認してから行ってください。

1. 下書きの画面で、「**Edit**」を押します。
2. 必要なら、リリースの説明（変更点など）を書きます。
3. 「**Set as the latest release**」にチェックが入っていることを確認します。
4. 「**Publish release**」を押します。

### 7. 公開後に確認する

PowerShell で、次を実行します。`latest.json` が、認証なしで取得できることを確認します。

```powershell
curl.exe -sL https://github.com/ikaken/mailglance/releases/latest/download/latest.json
```

`"version": "0.2.0"` を含む JSON が表示されれば、成功です。

### 8. アプリの更新を試す

1 つ前のバージョンが入っている PC で、次を確認します。

1. アプリを起動して、15 秒ほど待ちます。右下に、「新しいバージョン 0.2.0 があります」と表示されます。
   - すぐに確認したいときは、設定画面の「**更新を確認**」を押します。
2. 「**今すぐ更新**」を押します。
3. ダウンロード → インストール → 再起動が行われます。
4. 設定画面で、「現在のバージョン：0.2.0」と表示されることを確認します。
5. アカウントや、メールの一覧が、そのまま使えることを確認します。

> 初回（`v0.1.0`）は、更新元となる古いバージョンがありません。更新の動作は、次のリリース（`v0.1.1` など）を出したときに、確認できます。初回は、インストーラーを入れて、起動できることを確認してください。

## うまくいかないとき

| 症状 | 原因と対処 |
|---|---|
| ワークフローが、「Tag … is not on main」で失敗する | タグを付けたコミットが、main にありません。PR をマージしてから、main に、タグを付け直します。 |
| 「Version mismatch」で失敗する | タグとファイルのバージョンが、一致していません。`node scripts/set-version.mjs <版>` で揃えて、PR をマージし、タグを付け直します。 |
| 署名のステップで失敗する（秘密鍵やパスワードのエラー） | Secrets の値が違います。余計な空白や改行が入っていないか確認して、登録し直します。 |
| 型チェックや Rust のテストで失敗する | 該当のログを確認して、コードを直し、PR をマージして、タグを付け直します。 |
| 下書きに `latest.json` や `.sig` がない | ワークフローの、ビルドのステップのログを確認します。`createUpdaterArtifacts` の設定と、Secrets を確認します。 |
| アプリが、更新を見つけない | 公開済み（下書きでない）の最新リリースか、`latest.json` を確認します。バージョンが、アプリより新しいことも確認します。 |
| 更新のダウンロードで失敗する | `latest.json` の `"url"` を、ブラウザで開いて確認します。署名のエラーなら、`.sig` の内容と、アプリの公開鍵（`tauri.conf.json`）が、同じ鍵のペアか確認します。 |

### タグを付け直す

ワークフローが失敗して、やり直す場合の手順です。

```powershell
# 下書きのリリースがあれば削除（Releases の画面から、Delete でも可）
gh release delete v0.2.0 --repo ikaken/mailglance --yes

# タグを、リモートとローカルから削除
git push origin --delete v0.2.0
git tag -d v0.2.0

# 直したあとで、もう一度タグを付けて、プッシュ
git fetch origin
git tag v0.2.0 origin/main
git push origin v0.2.0
```

> **公開済みのリリースは、削除しないでください。** すでに更新を受け取ったアプリが、あるかもしれません。問題があれば、より新しいバージョンを出して直します。

## 補足

- **`latest.json` の URL は、GitHub の API の URL です。** 更新プラグインは、認証なしで、この URL からインストーラーをダウンロードします（公開リポジトリなら、ファイル本体へ転送されます）。認証なしの API は、同じ IP アドレスから 1 時間に 60 回までなので、同じ IP の多数の PC が、一斉に更新すると、上限に当たることがあります。
- **Windows のコード署名について。** インストーラーには、Windows のコード署名（Authenticode）がありません。初回のインストールで、SmartScreen の警告（「Windows によって PC が保護されました」）が出ることがあります。「詳細情報」→「実行」で進めます。更新用の署名とは、別のものです。
- **秘密鍵が漏れたとき。** 攻撃者が、偽の更新を作れます。リリースを止めて（下書きにするか、削除して）、新しい鍵を作り、新しい公開鍵を入れたアプリを、手動で入れ直してもらいます。
- **秘密鍵をなくしたとき。** 新しい鍵を作り、新しい公開鍵を入れたアプリを、手動で入れ直してもらいます。入れ直すまでは、古いアプリは、新しい更新を受け取れません。
- 設計の背景は、[設計メモ](Gmail%20専用%20Windows%20アプリ%20設計メモ.md) の「配布と自動更新」を参照してください。
